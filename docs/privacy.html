What this site does with your data

This page is written by hand from the site's own source code. It describes every third-party service the browser actually contacts, every key written to your browser's local storage, and everything that is never stored anywhere.

LAST UPDATED: 22 NOVEMBER 2026

The short version

  • No analytics, no tracking pixels, no advertising beacons, no fingerprinting. Nothing on this site measures who you are or follows you around the web.
  • No server-side visitor logging. This is a static site on GitHub Pages. There is no application server that could keep a log of you.
  • Your game scores, quiz results, and settings stay in your browser unless you choose to sign in, in which case they are saved to a database row that only you can read.
  • A handful of free public APIs are contacted so the page can show local weather, live headlines, and — only when you press the button — answers to your own code questions. Each one receives the ordinary network information that any website request reveals — your IP address.
  • Nothing is sold, shared, or used for ads. There is no third party that profiles you because of this site.
  • The site describes itself to search engines and AI agents in plain text. A static file and a small JSON file list what this site is, which pages exist and which public APIs it uses. They are read by the crawler or agent that asks for them; they are not sent to any third party and they carry no information about you.

Third-party services the browser contacts

These are the only external services this site talks to. Every request goes from your browser straight to the service — the site has no server in the middle to relay it. Each service therefore sees your IP address and the standard details your browser sends with any request. There is no account identifier, no cookie, and no visitor ID attached to these requests.

Good to know: the IP lookup providers and the headline APIs all receive your IP address simply because that is how the internet works — any website you visit sees the same thing. What this site does not do is collect that address itself, write it down, or attach a visitor ID to it. The weather request is the only one that carries location, and it is deliberately rounded down before it is sent.

A small note on imon-auth-session-v1: it holds an access and refresh token for your Supabase session. That is standard for any "sign in with Google" site — it is how the site knows you are signed in — but it does mean that key is sensitive. Clearing site data signs you out and removes it.

On the server (the Supabase database)

This only applies if you sign in. The site uses one Supabase table called progress, which holds a single JSON blob per signed-in account:

  • What it holds: the same score and progress values listed above, plus your Supabase user ID and the time of the last update. Your name and email come from Google or GitHub via Supabase Auth, which stores them in its own user table.
  • Who can read it: only you. A row-level security policy ties every row to auth.uid() = id, and the browser only ever holds a publishable key — never a secret key. One player cannot read or overwrite another's row.
  • When it is written: after you sign in, the site merges your existing browser scores into your cloud row once, then pushes an update whenever a game writes a new score. Nothing is written for visitors who never sign in.

Never stored anywhere

  • Your IP address. The two lookup providers see it in transit, but the site never writes it down, in your browser or on the server.
  • Your exact coordinates. Only the rounded one-decimal values are sent to Open-Meteo, and they are not persisted.
  • Your postal code, city, or device location from the browser geolocation API. The location permission is optional, only used if you press "Use my location", and its result is rounded the same way and then discarded.
  • Any browsing behaviour — which pages you visited, how long you stayed, what you clicked, what you searched for.
  • Anything from the "Daily" section you did not ask for — the site reads public headline feeds and nothing else.
  • The code you write in the Code Lab. It stays in the editor and the preview frame in your own browser. Only a tag or property name you explicitly ask about is sent to the Stack Exchange search, and never the code around it.

No tracking, and what that means here

There is no analytics on this site

There is no Google Analytics, no tag manager, no Plausible, Matomo, Fathom, Hotjar, Microsoft Clarity, Sentry, Segment, Mixpanel, Amplitude, or any other analytics, error-reporting, or advertising tag anywhere in this site's code. There are no tracking pixels, no navigator.sendBeacon calls, no third-party iframes, and no third-party fonts or images loaded from someone else's server.

The only code that talks to the network is the handful of API calls listed at the top of this page, and each one is there to make a visible feature work.

One thing worth naming plainly: the site does use cookies — but only the ones a website cannot function without. If you sign in, the Supabase session needs a cookie to stay signed in. If you do not sign in, no cookie identifies you, and the site's own features do not need one.

There is also a service worker (sw.js) that caches the site's own files in your browser so the games keep working offline. It stores static assets of this site — HTML, CSS, JavaScript, images — in the browser's cache storage. It does not cache, store, or transmit anything about you, and it does not run any tracking.

How the site describes itself to AI agents

Two plain files let a search engine or an AI agent understand this site without guessing. Both are static, public, and carry nothing about you.

/llms.txt
A hand-written plain-text map of the site — what each page is, which public APIs the site contacts, and how it is built.Written by hand, not generated. It names the real pages, and the site checker fails the build if it points at a page that does not exist.
/.well-known/agents.json
The same information as structured JSON: entry points, machine-readable data files, third-party hosts, and the privacy posture of each one.Also checked by the site checker — a stale path in it fails the build.

Asking for either file is an ordinary web request, so the service that serves it sees your IP address. Nothing else is involved: no account, no cookie, no identifier, and nothing about you is written into either file.

What this site is not

A static site on GitHub Pages, with no server-side runtime

This site is a folder of plain HTML, CSS, and JavaScript files. It is published to GitHub Pages, which serves the files straight to your browser. There is no application server, no database behind the pages themselves, no PHP or Node runtime, and no code executing on a server that could log your visit. The only server-side component anywhere is the optional Supabase project used for sign-in and cloud save, and that is described above.

Put simply: there is no place where a record of "who visited this page" could be kept, because there is no server keeping records of visits.

If this page ever changes

If a new third-party service is added, this page is updated before that service ships. The date at the top of the page is the last time someone edited it by hand — this site has no build step and no automated privacy-policy generator, so a change made to the code on the same day may not be reflected here yet. If in doubt, the source code is the truth: it is all public at github.com/sabbirimon ↗.
